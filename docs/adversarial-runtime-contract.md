# Adversarial multi-entry runtime postconditions

This behavior contract advances [issue #364](https://github.com/Project-Helianthus/helianthus-ha-integration/issues/364), a partial slice of [issue #105](https://github.com/Project-Helianthus/helianthus-ha-integration/issues/105). It describes the consumer boundary between entry lifetime, subscription delivery, identity verification and existing invoke safeguards. It changes no runtime behavior or public API. Nothing here declares stability before Helianthus 1.0.

**Proven** identifies source behavior or an available offline assertion, with its scope stated below; no test execution or runtime success is reported by this page. **Hypothesis** identifies a required postcondition awaiting implementation or adversarial evidence. **Unknown** identifies missing evidence or an undecided bound. These labels are separate from acquisition, admission, trust and codec/profile qualification. This contract makes no protocol decoding claims; such claims require the public native documentation contract first.

## Ownership and observable state

All examples are synthetic. Entries A and B have distinct runtime objects and coordinators. A-old and A-new denote successive lifetimes of A for reasoning about callbacks; they do not prescribe a new generation field, module or architecture. No endpoint coordinates or device models are needed. Entry identity, endpoint location and semantic target identity are distinct.

| Field or resource | Owner and meaning | Required observation |
| --- | --- | --- |
| `entry_id` / runtime object | HA entry; runtime is indexed by entry ID in `hass.data[DOMAIN]` | Removing A must preserve B's exact runtime and usable resources. Reusing A's ID must not make A-old callbacks valid for A-new. |
| `subscription_task` / WebSocket context | Task belongs to one entry's runtime; context belongs to that task | Cancellation requested, task completion and awaited context exit are separate observations. Calling `cancel()` proves neither completion nor successful close. |
| `unsub_listeners` / queued callbacks | Listener handles belong to that runtime | Unregistering prevents future registration-based delivery; already queued callbacks require separate evidence of harmlessness. |
| GraphQL session | Obtained through HA's `async_get_clientsession` | Entry cleanup must not close the HA-managed session and disrupt B. A task's WebSocket context can close independently. |
| Admin session and PV/storage/EVSE boundaries | Entry-scoped resources recorded on runtime | Await each applicable close; record failures independently. Fixed shared services remain while another registered entry needs them. No teardown result may imply a failed close succeeded. |
| `instance_guid` | Verified logical gateway identity, normalized by identity helpers | Transport failure supplies no replacement identity. When an expected GUID is supplied, a different valid GUID is a terminal mismatch for that verification attempt. |
| host, port, path, transport | Candidate endpoint location, compared separately by `same_endpoint` | A verified location change is not a new entity identity. Preserve existing entity unique IDs. Version metadata is not identity proof. |
| zones / DHW / freshness / admission | Per-entry coordinator state and existing target-specific write fences | Retain partial last-known-good values according to existing merge/freshness policy; retention never grants fresh status or trust. An explicit absence is distinct from a missing field. |

## Six adversarial traces

Each row states the desired postcondition, not a claim that the whole trace currently passes. “Awaited close” includes the task's WebSocket context exit where applicable. A close error is an observed failure; it is not an authoritative identity mismatch. A retry is allowed only through existing lifecycle or read paths with current safeguards; it does not authorize replaying an uncertain invoke.

| Trace / owner | Trigger and transition | Awaited close | Retained state | Allowed retry | Unaffected sibling |
| --- | --- | --- | --- | --- | --- |
| T1 — A cleanup and its subscription task | Cancel A while its context exit or an entry-owned close raises: active → stopping → failed teardown, never silently complete | Observe task termination and context exit; await applicable resource closes. Preserve cancellation and close failure as distinct outcomes. A failure must not hide unattempted cleanup. | Preserve evidence of the failed/pending resources and prevent A-old publication. Do not claim runtime retention currently exists after successful platform unload. | Existing HA cleanup may retry unresolved A resources when safe; no automatic retry policy or deadline is introduced. Never replay invokes on cancellation. | B's task is not cancelled, B's context/session stays open, B's last-known data and trust are unchanged. |
| T2 — A platform unload and reload owner | Platform unload returns false, then HA retries: active → retained → retry → unloaded; reload may then construct A-new | First attempt: no resource close or cancellation. Successful retry: await A's task completion/context exit and applicable owned closes before claiming complete teardown. | On false, retain the identical runtime, subscription and listeners. On completion, retain config/entity identity; do not carry stale callback authority into A-new. | HA may retry unload; successful unload can precede reload. False unload is not permission to create a second runtime. | B's runtime object, listeners and service route remain usable throughout both attempts. |
| T3 — A-old listener/subscription delivery | A unloads, A-new starts, then a queued A-old semantic callback or message arrives | Establish completion of A-old task exit and unsubscribe calls; late delivery must remain harmless even if it was queued before unsubscribe | Preserve A-new's data, freshness, admission and reload scheduling; preserve A-old native evidence without publishing it as current. No old callback may schedule a new reload or invoke. | A-new may poll and process its own current notifications. Dropped old delivery must not trigger a write retry. | B receives only its own updates; no B reload, data replacement or service removal. |
| T4 — A subscription and polling coordinators | Connection init → delayed/missing acknowledgement → read fallback; later normal acknowledged connection | No subscribe before acknowledgement. On cancellation/failure, observe context exit before claiming connection released; absence of acknowledgement alone is not a close result | Keep valid partial coordinator data and its existing freshness markers. Polling must remain available; subscription traffic must not postpone the full-poll deadline. | Existing polling may refresh. A new subscription attempt, if scheduled by existing lifecycle, must acknowledge again. No reconnect loop or timeout is invented here. | B's acknowledgement, subscriptions and poll deadline are independent; A's missing acknowledgement cannot block B. |
| T5 — A identity verifier | Candidate one has request/timeout failure; next candidate matches or returns terminal identity evidence | Verifier borrows its session; no entry/session teardown is implied. Any separately cancelled subscription still requires T1's context-exit evidence | Preserve configured identity and last-known state on transient failure. With an expected GUID, accept normalized match; mismatch, malformed response, missing GUID or schema error terminate that attempt with their own reasons | Advance candidates only for request/timeout failures. All-transport-failure yields `cannot_connect`; a terminal response cannot be bypassed by a later matching candidate. A future read attempt is distinct from silently rebinding identity. | B's configured identity, endpoint and admission are not changed by A's candidate outcomes. |
| T6 — A resource/service owner with B still loaded | A unload succeeds while B holds another runtime and entry service route; A-owned close fails or completes | Await A's Admin session and PV/storage/EVSE boundary closes as applicable; never close the shared HA GraphQL session. If an early close fails, later resources cannot be called released without evidence | Keep B's service registration and routing. Record A's unresolved cleanup accurately; preserve existing trust/admission and entity unique IDs. No receipt/ledger or recovery design is prescribed | Only safe unresolved-resource cleanup through existing lifecycle. An unavailable A service must not reroute to B. No action replay on B | B's session, boundary objects and response routing remain valid; fixed services are removed only when the last registered entry unloads. |

Required observation order is partial, not a duration promise: platform failure precedes retention; acknowledgement precedes subscription registration; successful teardown requires evidence of awaited exits; a replacement lifetime must reject old effects. Numeric cleanup, acknowledgement and recovery deadlines are **Unknown** here. A future executor must supply explicit durations and thresholds and distinguish timeout from completion; this document cannot satisfy that parent acceptance by choosing arbitrary numbers.

## Current evidence and explicit gaps

| Obligation | Current source / available assertion | Gap against the trace |
| --- | --- | --- |
| T1 cancellation with failing close | **Proven source:** [entry cleanup] cancels the task but does not await it; runtime is popped before owned closes. It awaits Admin, PV, storage and EVSE closes sequentially. Ordinary unsubscribe exceptions are suppressed. [Subscription client] uses an async WebSocket context and catches ordinary exceptions; [Admin coordinator] awaits awaitable session close without suppressing failure. | **Hypothesis:** complete cancellation/close-failure isolation. **Unknown:** task drain, preservation of cancellation during close failure, release of later resources after an earlier error, retryable cleanup ownership and B isolation. Current cleanup can lose the runtime reference before a close fails; do not report safe retry as implemented. |
| T2 failed unload and reload | **Proven source:** [entry cleanup] gates removal/cancellation on platform-unload success. **Proven available assertion:** `test_unload_failure_preserves_runtime_for_home_assistant_retry` in [entrypoint tests] checks false, identical runtime and no cancellation. | **Unknown:** false → success retry with real task drain, each owned close, no duplicate runtime and B unaffected. The existing assertion covers only the false branch. |
| T3 late callback after unload | **Proven source:** [entry setup] registers entry listeners and captures a local `reload_scheduled` flag; its semantic listener schedules entry reload for newly available inventory. [Entry cleanup] unsubscribes listeners. **Proven available assertion:** `test_adv04_replay_reaches_semantic_inventory_transition` in [offline harness tests] checks the actual delayed-inventory predicate path. | **Hypothesis:** no effect from A-old delivery after unload/reload. **Unknown:** no lifetime guard is established by these anchors; [subscription client] dispatches to the supplied coordinators without an entry-lifetime check. Unsubscribe and a per-setup reload flag do not prove queued-callback rejection. |
| T4 acknowledgement and fallback | **Proven source:** [subscription client] awaits `_wait_for_ack` after init and before subscribe; it has no local acknowledgement deadline or reconnect loop, and non-text frames during acknowledgement are simply continued. [README] describes polling fallback. [Coordinator] configures periodic refresh and `_publish_subscription_data` preserves the scheduled full poll. **Proven available assertion:** `test_subscriptions_wait_for_acknowledgement` in [handshake tests] checks the ordering and normal context exit for required/optional subscription combinations. | **Unknown:** missing acknowledgement/CLOSE/ERROR termination, failing context exit, actual polling recovery and cross-entry deadline isolation. The test's watchdog is a test bound, not a production acknowledgement timeout. |
| T5 identity failure precedence | **Proven source:** [identity helpers] normalize/deduplicate candidate hosts, continue only on request/timeout errors, and return terminal reasons for invalid responses, missing GUID, schema error or expected-GUID mismatch. **Proven available assertions:** `test_terminal_response_after_transport_failure_stops_before_match` and `test_mixed_transport_failures_reach_normalized_third_endpoint` in [failover tests]; [final-candidate tests] retain terminal reasons after two transient errors. | **Unknown:** end-to-end HA entry retention and B isolation during probing. Expected-GUID rejection is conditional: [entry setup] initially calls verification with `expected_instance_guid=None` and then handles configured/live identity reconciliation. Do not infer universal fail-closed setup rejection from the helper tests or redefine reconciliation here. |
| T6 ownership and shared services | **Proven source:** [entry setup] obtains the HA-managed session and stores per-entry resources; [entry cleanup] targets the entry key. [Integration boundary] unregisters the entry's Admin service route before awaiting its session close. **Proven available assertion:** `test_successful_admin_boundary_setup_and_final_unload_close_session_and_remove_services` in [Admin wiring tests] checks distinct clients, services surviving first unload, final removal and two close calls. | **Unknown:** full entry teardown with B active, failures across every close position and no wrong-entry routing after failure. The boundary test does not assert B data continuity or all M2M resources. No current “exactly once under retry” guarantee is inferred. |

## Invoke and retained-state safeguards

Every trace preserves existing checks immediately before a climate write: configuration-register allowlist, client and target presence, target freshness, successful semantic refresh, target existence and current trusted source admission. [Climate implementation] raises on malformed invoke responses, false success or client errors; a subscription acknowledgement is not an invoke acknowledgement. A transport exception after sending an invoke does not prove that the action was not applied. Do not automatically replay it, invent success or switch the action to B.

**Proven available assertions** in [climate tests] include `test_climate_write_fails_closed_when_admission_untrusted`, `test_climate_write_uses_live_admission_transition`, `test_climate_retained_zone_is_readable_but_not_writable` and `test_climate_partial_zone_refresh_does_not_authorize_stale_sibling_write`. The last case covers two targets within one entry, not two HA entries. [Offline harness tests] exercise real zone/DHW write fences and failed-refresh availability through injected fakes. These assertions do not establish close-failure behavior or live execution. Admission/trust remain native safeguards; this slice introduces no new authorization gate before 0.9.

Partial subscription merge behavior retains omitted values and existing nested values when an update is null; explicit DHW absence has its own handling in [subscription client]. As [README] explains, empty zones and null DHW do not prove native removal: the API supplies no completeness, tombstone or generation signal, so the existing bounded grace applies. Retained data must preserve its freshness limits and remains in memory only; it does not survive reload or identity generations. Retaining native evidence in these traces does not require transferring old readings into A-new. Do not promote another target or entry to fresh because A received an update. No shared-snapshot, GraphQL schema, eBUS MCP envelope or parity behavior is redesigned here.

## Review discriminators and remaining acceptance

These are reasoned mutation mappings for reviewing the contract, not executed mutants or new tests. For each trace, use distinct opaque A/B sentinels and independent expected outcomes; a shared or aliased baseline cannot prove isolation.

| Trace | Minimal synthetic observation | Production mutation that would violate the obligation |
| --- | --- | --- |
| T1 | A task blocked in context exit; failing close; B task remains running | Treat cancellation request as completed exit, suppress the close failure, or abort all remaining cleanup while reporting complete |
| T2 | First unload false, second true; same A runtime retained on first attempt; distinct B runtime | Pop/cancel A on false, or start A-new before old teardown completes |
| T3 | Capture A-old callback, unload, create A-new, deliver old callback; zero new effects | Permit old callback publication/reload against replacement runtime |
| T4 | Hold acknowledgement; observe only init; independent B progress and A full-poll deadline | Subscribe before acknowledgement, postpone full polling on every notification, or make B depend on A acknowledgement |
| T5 | Request failure followed separately by matching identity, mismatch, malformed data and schema error | Turn transient errors into mismatch, continue after terminal evidence, or accept mismatched expected GUID |
| T6 | Distinct A/B sessions and service routes; fail each A close separately | Close HA's shared session, remove B's route, reroute A to B, or claim unattempted resources closed |

Identity field review varies `entry_id`, runtime lifetime, expected/reported `instance_guid`, host, port, path and transport independently: wrong entry selection violates ownership; old lifetime reuse violates T3; GUID substitution violates T5 when an expected GUID is present; dropping any location comparison violates endpoint drift detection. None of these single-field mutations was executed here, and this page does not claim exhaustive field coverage in the existing tests. Version metadata changes must not substitute for GUID verification.

This slice adds no duplicate U07/U09/V04 tests, no M32 architecture change and no G5 D1–D5/O8 implementation. J01–J17 retain those boundaries; receipts, idempotency ledgers, principal boundaries and recovery redesign remain outside this contract. Existing native evidence, admission/trust, unique IDs, GraphQL parity and eBUS MCP compatibility are preserved.

Parent #105 remains open: executed restart, temporary partition, reconnect sync and delayed bootstrap scenarios, explicit durations/numeric thresholds, machine-readable runtime artifacts, full CI and the parent's separate physical/smoke acceptance are not supplied here. This page has no live executor or trigger. Real-HA smoke is optional supplemental integration evidence under repository guidance; it does not become a new CI gate, and this slice makes no claim to discharge the parent's historical smoke requirement. Any live action requires separate action-time operator confirmation.
