# Offline HA consumer acceptance boundary

This is the explanatory evidence slice for [issue #278](https://github.com/Project-Helianthus/helianthus-ha-integration/issues/278). Links identify existing source and test assertions on the issue branch; reading them supplies no new test PASS or operator observation.

**Proven** means a narrowly identified software assertion encoded in an existing offline test, conditional on its execution evidence; this document reports no test execution. **Hypothesis** means an expected live consequence awaiting observation. **Unknown** means evidence is absent here. These labels do not confer codec/profile qualification, protocol proof, authorization, or release stability.

| Boundary | Current implementation | Existing offline assertion and limit | Residual physical / HA observation |
| --- | --- | --- | --- |
| Optional-query support | [Availability helpers] and the [system coordinator] keep support state separate for installer and sensitive queries. `None` projects as available; a recognized missing schema field sets `False`; a response advances `None` to `True`; transient client errors preserve the state. [Boiler coordinator] uses the same helpers. | **Proven** assertion: [optional schema test] preserves the base system payload and sensitive-query availability when the installer field is missing. [Metadata test] preserves base data when optional metadata is absent. **Unknown** here: direct focused coverage of every helper transition and the equivalent boiler optional-query sequence. | **Hypothesis**: unrelated HA entities remain usable across optional-query absence and transient failure. **Unknown**: actual entity availability and recovery presentation on a real HA instance. Schema support is not permission to access a field. |
| Last-known energy data | [Energy coordinator] retains valid normalized totals and returns isolated copies through [energy copy helper] on invalid/missing totals or query errors. Before the first valid sample it returns `energy_totals: None`. A missing monthly field selects the existing legacy query. | **Proven** assertions: [energy retention test] retains a valid sample after null totals; [initial energy test] returns `None` after an initial client error and null totals; [monthly fallback test] selects and retains the legacy query choice. **Unknown** here: focused assertions for copy isolation and a transport error after a valid sample. | **Hypothesis**: an interruption preserves the last reading without inventing zero. **Unknown**: HA energy display, history/statistics, recovery and reload behavior. Retention does not establish freshness, persistence across restart, or the bounded zone/DHW grace policy. |
| Source admission with empty inventory | [Admission normalization] requires active state, a passed active probe and a parsed selected source; absent/incompatible source-selection data fails closed. [Empty-inventory guard] changes otherwise trusted admission to `empty_inventory_untrusted`. [Effective admission] retains raw admission separately and recomputes diagnostics from current inventory. | **Proven** assertions in [admission tests]: `test_empty_inventory_guard_marks_active_admission_untrusted` revokes trust; `test_update_effective_admission_reapplies_empty_inventory_guard` checks empty-to-nonempty recomputation and diagnostics; `test_legacy_admission_shapes_fail_closed` rejects alternate shapes. These helper assertions do not establish end-to-end HA cleanup or write suppression. | **Hypothesis**: HA surfaces the degraded state and existing guarded paths remain blocked until current evidence admits them. **Unknown**: real empty-inventory diagnostics, registry preservation, guarded-path behavior and recovery. These existing native trust/admission safeguards are distinct from user authorization; this slice adds no access gate before 0.9. |
| Teardown retry | [Entry cleanup] awaits platform unload first. A false result returns false without removing runtime or cancelling its subscription task; cleanup occurs only after platform unload succeeds. | **Proven** assertion: [unload retry test] checks false return, the identical retained runtime object and no cancellation event. **Unknown** here: a failed unload followed by a successful retry with all resources released exactly once. | **Hypothesis**: retained runtime permits HA to retry. **Unknown**: actual HA retry scheduling, entity/subscription continuity and eventual complete teardown; the test does not drive HA's retry lifecycle. |

## Remaining candidate evidence

Carry the four residual observations into the existing consolidated candidate process, attached to its candidate record. Observe optional-field absence/recovery, energy interruption/recovery, empty-inventory degradation/recovery, and failed-unload retry where the authorized environment permits. Record observed results separately from expectations; an unavailable scenario stays **Unknown**. Any live action requires explicit operator confirmation at action time. Real HA smoke is optional supplemental evidence, never a new mandatory CI or PR gate; the [existing smoke boundary] also leaves live restart/reset/partition procedures separately authorized.

This map does not replace K26 Ingress checks or M46 candidate indexing and does not close their acceptance. The future M30–M33 shared-snapshot consumer is **Unknown** in this slice: no shared-snapshot schema, revision, consistency, freshness or recovery contract is inferred from these per-coordinator helpers. That future consumer requires its own implementation and evidence against the then-approved public contract.

No runtime, GraphQL or eBUS MCP behavior changes here; this supplies neither a gateway API stability promise nor a new snapshot contract. All MCP namespaces remain pre-stable; no stability is declared before Helianthus 1.0. Protocol facts and codec/profile qualification remain outside this consumer map.
