# Legacy-covered sensor migration contract

This is the proposed migration contract for [issue #382](https://github.com/Project-Helianthus/helianthus-ha-integration/issues/382), a partial slice of Project #2. It specifies a later implementation decision after M33; it changes no sensor, descriptor store, API, or runtime owner. It does not replace the [shared snapshot consumer contract](https://github.com/Project-Helianthus/helianthus-ha-integration/blob/main/docs/semantic-snapshot-consumer.md) (M30). Nothing here promises stability before Helianthus 1.0.

**Proven** below means inspected source behavior only. **Hypothesis** means a proposed migration rule or synthetic expected result. **Unknown** means missing equivalence or runtime evidence. These evidence labels are separate from source qualification, acquisition, freshness, promotion and measurement admission. There is no new principal, credential or permission gate; authentication and authorization remain 0.11 work. Existing trust and admission checks remain mandatory.

## Source boundary and present behavior

The public sources for this inventory are:

- [Semantic sensors](https://github.com/Project-Helianthus/helianthus-ha-integration/blob/main/custom_components/helianthus/semantic_snapshot_sensors.py): `DESCRIPTORS`, `_descriptor`, `_source_admitted`, `SemanticSnapshotSensor._reading`, and discovery.
- [PV adapter](https://github.com/Project-Helianthus/helianthus-ha-integration/blob/main/custom_components/helianthus/pv_m2m.py): `_FACTS`, `_OUTPUTS`, `_candidate`, `_projection`, descriptor persistence and identity builders.
- [Storage adapter](https://github.com/Project-Helianthus/helianthus-ha-integration/blob/main/custom_components/helianthus/storage_m2m.py): `_FACTS`, `_key`, `_candidate`, `_projection`, descriptor persistence and identity builders.
- [Sensor setup](https://github.com/Project-Helianthus/helianthus-ha-integration/blob/main/custom_components/helianthus/sensor_setup.py): legacy creation and discovery listeners.
- [Sensor entities and metadata](https://github.com/Project-Helianthus/helianthus-ha-integration/blob/main/custom_components/helianthus/sensor.py): `HelianthusPVM2MSensor`, `HelianthusStorageM2MSensor`, `_pv_sensor_metadata`, and `_storage_sensor_metadata`.

Proven: discovery skips every descriptor with `legacy_covered=True`, regardless of whether that entry has a legacy entity. It does not reconcile registries or transfer ownership. There are exactly **14 flagged descriptor rows: seven PV and seven Storage**. This is a descriptor inventory, not a promise of 14 entities: phases expand, absent facts create none, and saved descriptors can survive without a current fact.

Proven: the legacy setup creates entities from saved/discovered descriptors and registers each coordinator's discovery listener. Both legacy sensor classes allow an AVAILABLE fact with FRESH or STALE freshness when the source/coordinator is available. Shared sensors instead require fresh evaluated input. Reusing a legacy ID alone would therefore not prove behavioral compatibility.

## Exact inventory and decisions

Notation: `P` is `helianthus.pack.pv` version `1.0.0`; `S` is `helianthus.pack.storage` version `1.1.0`. These are pack definition versions, not gateway versions. A new key below includes that pack, the fact ID and exactly one dimension with typed value `{kind: text, text: value}`. The enclosing opaque asset ID must equal the configured legacy asset reference `A` within config entry `E`; an approved identity mapping would be needed for any different asset ID. Labels, device families and positions cannot establish that mapping.

Old keys are `(fact_id, dimension_kind, dimension_value)` owned by the named legacy sensor class. `n` ranges independently over `L1`, `L2`, `L3`. Metadata is `HA native unit / device class / state class`; `none` means no class or unit. The old metadata column is binding for any future migrated entity, including recorder statistics. The seven candidate rows have a source-level mapping, not Proven end-to-end equivalence. All 14 remain under their old owners until a later owner implements and validates the transaction. Current shared `_reading` requires exactly one fact disposition, `exact`, empty loss, and inclusion of the complete key in `sourceKeys`. A transformed legacy projection cannot be relabeled exact or have its losses discarded to admit a shared reading. Even a new exact shared projection does not resolve old/new semantic continuity for a withheld row. Native interpretation requires the public native documentation contract first; this document supplies no protocol decoding or new native claims. Preserve source keys, loss kinds/source items/reasons, evidence references and access/redaction markers for audit.

### Exclusions without a matching legacy entity

No flagged descriptor family lacks a legacy mapping in the inspected tables. However, the flag excludes more possible instances than those mappings cover:

| Excluded instance | Why no matching old entity exists | Disposition |
| --- | --- | --- |
| PV phase text other than `phase:L1`, `phase:L2`, `phase:L3` | Shared descriptor matches arbitrary pack-valid text; old adapter accepts only those phases. | Withhold; do not strip arbitrary prefixes or invent a phase. |
| PV inverter dimension other than `inverter`, or system dimension other than `system` | Old adapter requires these exact semantic singleton values. | Withhold; never collapse distinct inverters/systems into scope total. |
| Storage pack text different from `A` | Old parser/store require the configured asset reference as pack dimension. | Withhold; no cross-asset migration. |
| A flagged key on an entry with no matching persisted/discovered descriptor, no legacy configuration, or no legacy entity | A static exclusion is not evidence of an installed entity or its registry identity. | No migration; leave excluded until a separate new-entity rollout decision. Never fabricate a saved unique ID. |

Conversely, persisted legacy PV descriptors may include `pv.ac.voltage.line_to_line`, `pv.ac.power.apparent`, `pv.ac.power.reactive`, `pv.ac.power_factor`, `pv.dc.current`, `pv.dc.voltage`, `pv.dc.power.active`, `pv.dc.energy.active_total`, `pv.event.flags`, and `pv.rating.ac.active_power`. These are outside this flagged set, even when a similarly named unflagged semantic fact exists. Leave them with their current owner. Storage's descriptor allowlist comprises the seven rows above. EVSE, Thermal and their controls/lifecycle migrations are outside this first set; Infrastructure is not a legacy-covered pack here.

## Preservation and per-entry transitions (proposed)

**R — identity and registry preservation.** For each approved pair, reuse the actual persisted `descriptor.unique_id`, the existing entity registry record/entity ID and its device association. Do not recompute or replace the ID with `semantic_unique_id`. Legacy builders derive the suffix from the ordered JSON tuple `[A, old_fact_id, dimension_kind, dimension_value]`, with entry/family prefix; their loaders permit persisted IDs under the entry prefix and do not establish a general full-key serializer. Retain the exact saved ID, not a guessed reconstruction. Keep `build_pv_device_identifier(E,A)` or `build_storage_device_identifier(E,A)` and the existing device registry record; do not move it to a semantic asset device. Preserve custom entity/device names, area, labels, icons, hidden/disabled settings, enabled default, user unit/display settings, recorder identity and old native unit/device/state classes. Disabled entries stay disabled and are still reserved against duplicate creation. Any metadata or registry conflict withholds that pair. The generic shared sensor class is not a drop-in replacement.

**U — unsupported/unknown gateway.** Before cutover, root support None/False leaves the old owner untouched and creates no shared replacement. Missing root sets unsupported, stops shared retries until unload/setup, per the consumer contract. After committed cutover, a lost root makes the migrated entity unavailable; it does not reactivate M2M. Only explicit rollback can restore that owner. Transient errors and missing subfields on a supported root reject the attempt, not establish a thinner supported API.

**S — stale, unavailable or missing input.** A proposed migrated entity requires the existing shared admission checks: coherent detached wrapper, current native source/binding/epoch/generation, qualified identity link with basis, observed/qualified/promoted/good/available quality, fresh evaluated availability joined by candidate identity and revision, exact loss-free projection and valid typed value/unit/range. Unknown policy, conflict, multiple candidates, missing evidence or unproven equivalence withholds migration. After cutover these conditions make the entity unavailable while retaining descriptors and last-known-good evidence. Legacy STALE grace is a documented behavior difference requiring later review; migration must not inherit it implicitly or pretend the shared policy already preserves it.

**L — partial state and loss.** A valid response with one unavailable asset keeps readable siblings; a malformed or mixed attempt retains the previous accepted detached state for diagnostics and marks affected live readings unavailable. Do not turn sparse publication into deletion. Keep original observation times, clocks/epochs, freshness policy, candidate revision and evaluated deadlines; receipt/reload time never rejuvenates evidence. Present exact zero remains zero, absent remains absent. Retained observations remain historical and cannot substitute for active candidates. There is no silent M2M, MCP, eBUS tool or reduced-query fallback on shared read failure.

**B — rollback boundary.** Before commit, abort staged mapping and leave old ownership/registry untouched. After commit, quiesce and fence the shared writer, retain all shared evidence and unavailable state, then restore old ownership from the saved descriptor/registry mapping only after cleanup and an explicit rollback decision. The old adapter must obtain a valid read under its own admission/freshness rules before reporting availability; a saved value is not a fresh read. Never run two writers or reset observation age. Reverting a rollout switch without reconciling its persisted ownership record is insufficient. Failed rollback cleanup leaves the pair unavailable with no active writer until recovery.

**I — interrupted reload.** Persist transaction intent and a committed ownership generation before enabling the new writer. On reload, reconcile that record before either legacy discovery or shared discovery can add an entity. Incomplete pre-commit intent resumes old ownership only after fencing any staged listeners. A committed record resumes shared ownership, initially unavailable pending a validated read. An ambiguous/corrupt record fails closed to no writer and keeps registry and descriptors for recovery. Old callbacks from earlier generations cannot publish, discover duplicates or overwrite ownership. This state machine is proposed; no such ownership journal or writer fence is claimed in the inspected setup.

## Proposed cutover transaction

1. Serialize work within config entry `E`; snapshot the descriptor and relevant registry settings without overwriting unrelated options. Build an explicit one-to-one map from `(E,A,complete new FactKey)` to `(old descriptor key, saved unique ID, device record)`. Validate pack version, dimension ID, typed arm and value byte-for-byte. Different entries cannot adopt each other's IDs, even for the same asset/key. Detect many-to-one maps, collisions with existing shared entities and disabled registry records; withhold conflicting pairs.
2. Stage only approved candidate rows with a currently admitted shared read and reviewed old/new value, unit, statistics and age continuity. Keep withheld rows under their legacy owners. Reserve migrated facts against generic shared discovery; do not merely flip `legacy_covered` globally. No equality of coincidental numeric values proves equivalence.
3. Record recoverable intent containing old ownership and mapping, then quiesce/fence old entity updates and discovery for the selected pairs. An old coordinator may continue serving unmigrated facts, but cannot write a migrated entity. Stop callbacks and await in-flight work before transferring ownership. Disabled records participate in reconciliation without being enabled.
4. Commit the ownership generation durably, then attach one shared-backed writer to each preserved entity identity/metadata. Publish only after admission and continuity validation; failure after commit follows S/L, not automatic rollback. Keep the old descriptor data for reversible recovery. Commit need not be globally atomic across entries; entry isolation is mandatory. If the chosen HA persistence/lifecycle primitives cannot guarantee this ordering, withhold implementation pending an owner decision.
5. Verify one writer and one registry entity per mapped pair, preserved settings/statistics, no replacement IDs and no extra discovery. Clean up subscriptions on unload. Exercise B/I before rollout. There is no authorization control or operation dispatch in this transaction.

The ownership record and persistence mechanism, HA reattachment behavior, continuity policy for transformed rows, and stale-grace decision remain Unknown. Implementing these needs a separate reviewed change; this prose does not authorize an API workaround. Keep deterministic public envelopes, native provenance, partial last-known-good state, legacy eBUS MCP compatibility and gateway GraphQL/MCP parity. HA does not call MCP to establish parity. G5 D1–D5/O8 and driver-owned eeBUS output binding remain unchanged.

## Synthetic acceptance cases and later owner decision

All cases below are Hypothesis expectations for offline tests, not executed evidence. Use synthetic opaque assets and detached fakes only.

| Case | Required result |
| --- | --- |
| PV phase:L1 voltage with one approved old descriptor; quantity zero | Existing ID/device/settings retained, zero published once; no generic semantic ID. Repeat independently for L2/L3 and current. |
| Two entries with the same asset/key, and two assets within one entry | No cross-entry adoption or cross-asset collapse; only exact configured mapping transfers. |
| Disabled/hidden old record with custom settings | Same record/settings and disabled state; reservation prevents duplicate semantic entity. |
| Unmatched phase text, extra dimension, typed non-text dimension, changed pack version or colliding old IDs | Withhold mapping; leave old owner; no guessed singleton or key coercion. |
| PV energy or Storage capacity with equal numeric old/new values | Still withheld: unit/state-class/policy evidence is required. Numeric equality is insufficient. |
| Transformed status with unsupported token or explicit withheld disposition | Preserve complete symbol/loss/reason; no guessed state or boolean and no migration. |
| One asset unavailable with readable sibling; later failed whole refresh | First result preserves sibling; failed refresh retains accepted evidence but is not a successful new measurement. |
| Previously admitted zero becomes stale/unknown, null, conflicted or unqualified | Entity stays registered and unavailable; original observation age preserved, no fabricated zero or legacy fallback. |
| Crash before intent, after intent, after old fence, after ownership commit, or during listener attachment | Apply B/I at each boundary; at most one writer, no duplicate discovery, unavailable until valid recovery read. |
| Rollback with pending old/shared callbacks; reload twice | Earlier generation callbacks rejected; saved IDs/registry untouched; restored owner must read successfully. |
